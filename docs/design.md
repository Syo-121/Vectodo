# タスク管理アプリ v1 設計（2026-10-13 確定）

要件の正= `docs/requirements.md`。この文書は **v1 の作り方**を決める。v2 以降に効く部分は「v2 で使う」と明記して、v1 から器だけ用意しておく。

## 1. 技術構成（2026-10-13 本人 OK）

| 部分 | 採用 |
|---|---|
| 言語 | TypeScript（画面・API・MCP すべて） |
| サーバ | Node 22 ＋ Hono。TS は `tsx` で直接実行 |
| DB | SQLite（Node 組み込みの `node:sqlite`。困ったら `better-sqlite3` へ） |
| 入力検証・型 | zod（スキーマを画面・API・MCP で共有） |
| 画面 | React ＋ Vite ＋ Tailwind CSS、TanStack Query（チェックを押した瞬間に反映＝楽観的更新）、PWA |
| MCP | 公式 TypeScript SDK。**アプリ本体の `/mcp` に Streamable HTTP で載せる**（下記） |
| テスト | vitest（日付・繰り返し・依存の判定を重点的に） |
| 公開 | アプリは `127.0.0.1` だけで待ち受け、`tailscale serve` で tailnet に HTTPS 公開。ログイン機能なし（tailnet が鍵） |
| 常駐 | systemd（WSL でも systemd が動く） |

**MCP の載せ方を当初の推しから変える**: 10/10 の推しは「アプリの HTTP API を叩く別プロセスの薄いクライアント」だったが、**アプリ本体に `/mcp` エンドポイントとして同居**させる。

- 理由: プロセスが1つで済む。Windows 側の Claude Code から WSL のプロセスを起動する橋渡し（`wsl.exe` 経由の stdio）が要らない。画面と同じサービス層・同じ検証を通るので、AI だけ挙動が違う事故が起きない。
- 登録: `claude mcp add --transport http --scope user task-app http://localhost:<port>/mcp`。Claude Code はアプリと同じマシンで動かすので、URL は localhost のまま。

## 3. データモデル

### 3-1. tasks

| position | REAL | 兄弟の中での並び順（間に差し込めるよう実数） |

| category_id | INTEGER NULL → categories | |
| priority | INTEGER NULL | 1=高・2=中・3=低・NULL=未設定 |
| due_date | TEXT NULL | 締切日 `YYYY-MM-DD` |

### 3-2. task_dates（やる日・複数）

| 列 | 説明 |

| task_id → tasks | |

### 3-6b. memos（クイックメモ・要件 2-8・migration 003）

### 3-6e. notes（ノート・2026-10-14 本人要望・migration 008）

Google Keep のような自由なメモ。受信箱のクイックメモ（3-6b・振り分けて「済」にするもの）とは別に、残しておくもの。番号は `N-001`。

| 列 | 説明 |
|---|---|
| title / body | タイトルと、文章のノートの本文 |
| kind | `text`（文章）・`list`（チェックリスト） |
| items | チェックリストの項目 `[{"text","done"}]`（JSON） |
| color | 色（`red`〜`gray` の10色・NULL＝なし。Keep と同じ並び） |
| labels | ラベル `["買い物", …]`（JSON。前後の空白を落とし、同じものは1つに） |
| pinned / archived | 固定・アーカイブ |

- 並びは固定が先、あとは新しい順。探すのはタイトル・本文・項目・ラベルから。中身が空のノートは作らない。
- API: `GET /api/notes`（`archived=1`・`q`・`label`）・`GET /api/notes/labels`（使っているラベルと件数）・`POST`・`PATCH /api/notes/:id`・`POST /api/notes/:id/append`・`DELETE /api/notes/:id`。
- MCP（本人の選択「読む・書き足すまで」）: `list_notes`・`add_note`・`append_to_note`（チェックリストには未チェックの項目として、文章には末尾の行として足す。既にある中身は変えない）。⛔ 書き換え・削除・チェックを付ける道具は持たせない（画面から）。
- ⛔ パスワード・カード番号などは書かない（Claude が読めるため。画面の下にも書いてある）。

### 3-6f. goals・goal_logs（目標と、その記録・2026-10-20 本人要望・migration 009）

「週に2回運動」「本を1日10ページ」のような、決めた量を続けられているかを見るもの。タスク（やったら終わる）とは別。番号は `G-001`。

| 列（goals） | 説明 |
|---|---|
| title | 名前 |
| kind | `rate`（期間ごと＝1日・1週・1か月に◯◯）／`total`（期限までの総量＝12/31 までに 300 ページ） |
| period | rate のとき `day`・`week`（月曜はじまり）・`month` |
| target / unit | 目標の量と単位（既定 `回`。`ページ`・`分` など自由） |
| start_date | 数え始める日。省くと rate は今の期間の頭（今週の月曜・今月1日）、total は今日 |
| end_date | total は期限（必須）。rate は終わる日（NULL＝ずっと） |
| notes / position / archived | メモ・並び順・アーカイブ |

| 列（goal_logs） | 説明 |
|---|---|
| goal_id → goals | 目標を消すと記録も消える |
| date / amount / note | やった日・量（正の数・小数可）・一言 |

| 列（goal_plans・目標をやる時間・4-14・migration 010） | 説明 |
|---|---|
| goal_id → goals | 目標を消すと予定も消える |
| date / start_time / minutes | やる日・始める時刻（NULL＝時刻なし＝終日の段）・長さ（量は持たない＝記録するときに決める。migration 011 で amount の列を外した） |
| log_id → goal_logs | 結んだ記録（＝やった）。記録を消すと NULL に戻る |

migration 010 では、Google に書き出した予定の表（3-6c `gcal_events`）の slot の決まりも広げた（`goal:<予定の番号>` を入れられるように。SQLite は CHECK を書き換えられないので表を作り直して写した）。

### 3-7. 番号の桁（2026-10-13 本人の懸念「999 の次で溢れる」への対応）

- 番号は**整数で持つ**ので上限はない（999 の次は 1000）。桁を固定した文字列として持たないから、溢れは起きない。
- **表示は「最低3桁」**: 100 未満は 0 で埋めて `T-060`、1000 以上は `T-1000` のようにそのまま出す。
- **並べ替えは常に整数で**行う。文字列で並べると `T-1000` が `T-999` より前に来てしまうので、文字列では並べない。
- **検索・MCP の入力は表記の揺れを吸収する**: `T-60`・`T-060`・`t60`・`60` は、どれも同じタスクとして扱う。

## 4. 振る舞いのルール

### 4-1. 「今日」の判定（日付は常に JST）

- **今日やる**: やる日に今日が入っている未完了のタスク。
- **持ち越し**: やる日が全部過去で、まだ終わっていないタスク。「今日やる」に混ぜて、`持ち越し` の印を付ける。
- **期限切れ**: 締切日が過去で未完了のタスク。
- **締切間近**: 締切が今日から7日以内で、上の3つに入っていないタスク。

### 4-2. 依存待ち（薄く表示）

依存先に `done`・`canceled` 以外のものが1つでも残っていれば「依存待ち」と判定する。状態の列には持たず、毎回計算する。中止された依存先は「もう待たない」とみなす。

**祖先（親・その上）が依存待ちか状態「待ち」なら、その子孫も依存待ち**（2026-10-20・4-3）。例: 機能B が機能A を待っていれば、機能B の下の工程はまだ手を付けられない。サーバの `hydrate` が `blocked` に含めて返し、自分で待っている祖先のうちいちばん近いもの（＝待たせている元）を `waitVia` に入れる。行には「⛓ 親が待ち: T-xxx 機能B」、MCP は `依存待ち:親T-xxx`。

**状態が `waiting`（他人・結果待ち）のタスクも同じように薄く表示する**。添え書きは、依存待ちなら `待ち: T-130 ◯◯`、状態が `waiting` なら `待ち`＋メモの1行目にする。

### 4-3. 子と親

- 親の完了は子と独立（要件どおり）。
- 一覧では、親の行に子の進み具合（`2/5`）を出す。
- **親はまとめ役（2026-10-20 本人要望「少しでも大きいタスクはシリーズで管理したい・でも実際にはやらない親が画面に出てくる」）**: 子が残っている親（未完了の子がある＝`children.total > children.done`）は、やることそのものではなく案件・プロジェクトのまとまりとして扱う。振り分けは `src/shared/series.ts`（純粋関数・サーバと画面で同じ）。
  - **並べる画面**（今日の「次にやること」〜「近いうちに」・カンバン・重要×緊急・計画待ち・MCP の今日の各節）には親を出さない。**親の締切は「いま着手できる子」（未着手・進行中で依存待ちでない）に受け継がせる**（`forAction`）——自分の締切がある子はそのまま、祖先が複数あればいちばん早い締切、待ち・依存待ちの子は受け継がない（前の工程が終わったら受け継ぐ）。受け継いだ締切は行に「（親）」と出す（`dueFrom`・API は返さず画面で計算）。「次にやること」は 4-10 のとおり親の段を子へ渡す。
  - **日付の画面**（日・週・月）では、親は締切の印だけ（親のやる日は出さない＝やる日は子に付ける・`forCalendar`）。
  - **ボトルネック・振り返り・一覧・シリーズの図**はそのまま（依存のつながり・終わったもの・木の見出しとして親を見るため）。
  - ボードの「シリーズ（親）も出す」（既定オフ・端末に覚える）を入れると、親も子もそのまま出す（受け継ぎもしない）。それまでの「子タスクを含める」（子を隠すスイッチ）は置き換えた。
  - **子が全部終わった親**（中止した子は数えない）は、並べる画面にも「次にやること」にも、上の親の「いま着手できる子」にも入れない。**締切かやる日がある親と、中間の親（さらに上に親がいる＝機能・段階）**は、今日に「子が全部終わった」として［閉じる］つきで出す（`closable`・本人決定。中間の親は締切が無くても聞く＝閉じないと、それを待つ後ろの工程がずっと依存待ちになるため・2026-10-20）。いちばん上の親で締切もやる日も無いもの（続いていく開発のプロジェクトなど）は黙って残す。
  - **2段目より下の親**も同じ扱い（子を持つ子もまとめ役）。受け継ぐ締切は祖先のうちいちばん早いもの、親が待っていれば子孫も待ち（4-2）。シリーズの図は1段ずつ（孫は子のノードの「子 2/5」から入る）。
  - MCP: 親の行は `シリーズ0/7 次:T-155`（次＝いま着手できる子・無ければ `次:なし`）、子が全部終わった親は `子3/3 全部済`。今日（`view=today`）は親を期限切れ・今日やる・締切間近から外し、締切が7日以内の親を「シリーズの締切」、閉じる候補を「子が全部終わった（閉じる？）」に出す。

### 4-4. 繰り返し

- 1つのルールにつき、**未完了の回は常に1つだけ**にする（溜まっていかない）。
- 今の回を完了・中止すると、次の回を作る。次の回は、今の回の内容（タイトル・カテゴリ・優先度・見積・親・メモ）を写して作る。子と依存は写さない。
- 次の回の日付:
  - weekly・monthly: 「今の回の日付」と「今日」の遅いほうを基準に、それより後で最初に条件に合う日。サボった回は積み上げずに飛ばす。
  - interval: 今の回の日付＋N 日。それが過去なら、未来になるまで N 日ずつ足す。
  - after_done: 完了した日＋N 日。
- 「今回は飛ばす」は中止として扱う（次の回が作られる）。

### 4-5. 削除

- 削除は画面の確認ダイアログを通す（子があれば件数を出す）。
- 普段は「中止」を使う想定。
- **MCP には削除を持たせない**（AI は中止までしかできない）。

### 4-6. カテゴリのアーカイブ（終わったカテゴリを片付ける・2026-10-13 本人要望）

- 完了したタスクはもともと消えない（今日はその日だけ・ボードは7日・一覧は「完了も」で全期間）。カテゴリ（＝組織・プロジェクト）が丸ごと終わったら、**カテゴリをアーカイブするとそのタスクが今日・ボード・一覧・検索から隠れる**。タスク1件ずつに印は付けず、カテゴリの `archived` から決める。詳細（`GET /tasks/:id`）は開ける。
- 一覧の「アーカイブしたカテゴリのタスクも出す」（API は `includeArchived=true`）で見返せる。アーカイブ分は**完了・中止も含めて全部**出す（終わった記録として見るため）。カテゴリを指定した取得は、アーカイブ済みでもそのカテゴリを返す。
- **未完了が残っているとアーカイブできない**（隠れたまま締切が過ぎるのを防ぐ）。画面は未完了の名前を見せて「全部中止にしてアーカイブする？」と聞き（本人決定）、`cancelOpen=true` で全部中止にしてからアーカイブする。中止したタスクのメモに `中止: カテゴリ「X」をアーカイブ（日付）` を足す。繰り返しは次の回を作らないよう止める。
- 戻すとタスクはまた出る。止めた繰り返しは止まったまま（必要なら設定し直す）。

### 4-7. Google カレンダーへの一方向同期（v2・2026-10-13 本人決定）

**アプリ → カレンダーの一方向**。カレンダー側で変えたものはアプリへ戻さない。通知（スマホ）を取り戻すのが目的。

- **何を書き出すか**: 未完了タスクの**締切**と**やる日**。締切 = `【締切HH:MM】タイトル`（時刻あり: 締切の1時間前〜締切）／`【締切】タイトル`（日付だけ: 終日）。やる日 = `【タスク】タイトル`（終日・日ごとに1件）。やる日が締切と同じ日なら締切の予定にまとめる。**時刻を決めたやる日**（4-11 の空きに置いたもの）は、その時刻から配分時間（無ければ見積・どちらも無ければ 30m）の時刻つきの予定にし、通知は始まる5分前だけ。締切と同じ日でもまとめずに別の予定にする（2026-10-14）。繰り返しは回ごとに書き出す（完了すると次の回の予定ができる）。
- **通知**: 前日 20:00（全部）＋時刻つきの締切は締切の2時間前。色は締切=赤（11）・やる日=青（7）。
- **目標をやる時間**（4-14・2026-10-20〜）も `【目標】…` として書き出す（緑・10）。
- **説明欄**: `タスクID: T-NNN（Vectodo で管理）`／`優先度: 高・見積 1h`／カテゴリ／（やる日の予定なら）締切と配分／タスクを開く URL。⛔ **メモ欄は送らない**（送るのはタイトルと上の項目だけ）。
- **書き込み先**: カテゴリごとにカレンダーを選ぶ（設定画面）。未設定は「既定」（つないだときに「その他」を自動で選ぶ）。つないだとき、名前が同じ（か、それで始まる）カレンダーがあるカテゴリは自動で結ぶ。カテゴリや書き込み先を変えたら予定ごと移す（`move`）。
- **完了・中止**: 予定は消さずに `【済】`／`【中止】` を頭に付けて、通知を外す（本人決定）。戻したら元に戻る。
- **やる日・締切を消した／タスクを削除した**: **アプリが作った予定だけ**アプリが消してよい（本人決定。AI がカレンダーの予定を消すときは毎回確認する、という運用の例外）。アプリの予定には `extendedProperties.private.vectodo=1` の印を付け、`gcal_events` に覚えているものしか消さない。自分で入れた予定にはさわらない。
- **過去の予定はさわらない**（作らない・直さない・消さない）。
- **いつ同期するか**: 画面・MCP で書き込むたびに2秒待ってから（続けて書けば1回にまとまる）＋10分ごとに全体を見直す（通信に失敗しても次で追いつく・日付が変わったぶんも拾う）。失敗は状態に残し、設定画面に出す。
- **以前の管理方法で作った予定を引き取る（一度だけ）**: 取り込んだタスクのメモ欄にある「カレンダー: 「<カレンダー名>」`eventId`」を読み、今の締切・やる日と同じ日の予定なら、それをアプリの予定として覚えて今の形に書き換える（二重に作らない・9）。旧い繰り返しの予定は引き取らず、本人の承認を取って消す。
- **認可**: OAuth の「デスクトップ アプリ」型＋ループバック（戻り先 `http://127.0.0.1:<port>/oauth/callback`）。スコープは `calendar.events`（予定の読み書き）と `calendar.calendarlist.readonly`（カレンダー一覧）だけ。⛔ クライアントの JSON とトークンは `~/.config/task-app/`（0600・リポジトリに入れない）。つなぐのは PC のブラウザで（スマホからは 127.0.0.1 に戻れない）。⚠ Google Cloud の同意画面が「テスト」のままだとトークンが7日で切れる→「本番環境」に公開しておく。
- 外部ライブラリは使わず fetch だけ（`src/server/gcal/`: `plan.ts`＝何をどうするかの純粋関数、`sync.ts`＝実行、`google.ts`＝認可と API）。

### 4-10. 次にやること（2026-10-14 本人要望）

### 4-11. 今日の流れ（2026-10-14 本人要望）

### 4-13. 目標の進み具合（2026-10-20 本人要望）

- 記録は日付と量だけ持ち、進み具合は毎回計算する（`src/shared/goals.ts` の `goalProgress`・純粋関数で、サーバ・MCP の文・画面で同じもの）。
- **期間ごと（rate）**: 期間ごとの合計を出し、目標の量に届いたら「達成」。

- **タスクとはつながない**（本人の選択ではなく最初の形として AI が決めた）: タスクの完了で目標に自動で足すことはしない。続けることを見る道具なので、記録は［＋］1回で済むようにした。→ いつやるかは、タスクではなく次の「やる時間」（4-14）で決める（2026-10-20 本人決定）。

### 4-14. 目標をやる時間（2026-10-20 本人要望「1日10ページって決めたなら、それをいつやるかの実行時間を登録したい」）

- **タスクは作らない**（本人決定「タスクとしては作らず、月ビューや週ビューで登録する時に候補に出すのが良い」）。目標ごとに「やる時間」（日付・時刻〈無しでもよい〉・長さ）を持つ（3-6f `goal_plans`）。**量（何ページやるか）は入れない**——目標の名前だけで入れ、量は記録するときに自分で決める（2026-10-21 本人要望「何ページやるかとかはこっちで決めたい・ページ数とか単位とかはいれずに、タイトルだけいれてほしい」）。
- **入れ方**: ①時間割（今日の流れ・ボードの日・週）で時間を選ぶと、置くパネルの上に「目標をやる時間にする」として数えている目標が並ぶ（押すとその時間に入る・長さは選んだ長さ、「見積どおり」なら 30m）②月ビューの選んだ日の［🎯 目標をやる時間を入れる］③目標の詳細の［🎯 やる時間を入れる］④ Claude の `plan_goal`。数え始める前の日には入れられない。アーカイブした目標には入れられない。
- **見せ方**: 緑（emerald）で、タスク（藍）と見分ける。時間割（今日の流れ・日・週）には時刻つきは緑の枠、時刻なしは終日の段のカード。月はマスに緑の札（スマホは緑の点）と、選んだ日の下にカード。今日の画面の目標の行に「🗓 21:00 にやる」、目標の詳細に「やる時間」（今日から先のまだのもの・1週間以内に過ぎて記録していないもの＝「まだ記録していない」）とカレンダーの緑の点。今日の流れの空きの数え方では、置いたタスクと同じに時間を使う扱い。
- **動かす**: 時間割では置いたタスクと同じ操作（ドラッグで動かす・別の日へ・下の端で長さ・終日の段へ落とすと時刻なし）。時間割はタスクのやる日で動くので、予定1件を「やる日が1日だけのタスク」の形に写して渡し（番号は負＝タスクとぶつからない）、結果を予定の書き換えに戻す（`web/goalPlans.ts`）。記録のシートの「時間を変える」（日付・時刻・長さ・時刻なし）でも変えられる。
- **押すと記録のシート**（7-15）が、上にその予定（日付と時間・済の印・［時間を変える］［外す］）を出して開く。量は空で開く（「回」の目標は 1）。記録するとその予定と結ばれて**済**（緑の薄い枠に ✓）。先の日の予定は記録できない（時間を変える・外すだけ）。
- **記録との結び**: 予定から記録したらその予定。そうでなくても（今日の画面の［＋1］・Claude の `log_goal`）、その日にまだ済んでいない予定があれば最初のものと結ぶ（やったのに予定だけ残るのを防ぐ）。記録を消すと結びが外れてまだに戻る。予定を外しても記録は残る。
- **Google カレンダー**（本人決定「書き出す（5分前に通知）」・4-7）: `【目標】回路の本`（目標の名前だけ）を既定のカレンダー（その他）へ、色は緑（10）。時刻つきはその時刻から長さ（無ければ 30m）・5分前に通知、時刻なしは終日（前日 20:00 に通知）。説明欄は `目標: G-001 1日に10ページ（Vectodo で管理）` と目標を開く URL。済んだら `【済】` を付けて通知を外す。外す・アーカイブすると今日以降の予定は消える。`gcal_events` には task_id 0・slot `goal:<予定の番号>` で覚える。

**時間割の操作**（日・週・今日の流れで同じ・`components/TimeGrid.tsx`）: 空いているところ（予定の上でもよい＝ながら）をドラッグして時間を選ぶ → 置くパネルでタスクを選ぶ。タップならその時刻から。置いたタスクはドラッグで動かす（別の日へも）・下の端で長さを変える・上の「終日」の段へ落とすと時刻を外す。終日の段のカード（時刻の無いやる日）は、別の日の終日へ落とすとやる日が移り（そこにあれば時間を足す＝前の週と同じ）、時間の欄へ落とすとその時刻に置く（長さは配分、無ければ見積、無ければ 30m）。完了したものは薄く・動かせない。指は長押しから。置くパネルは時間割に重ねない（広い画面は時間割の右の列・それ以外は下半分）。候補は「次にやること」の順（今日から見た順）で、候補に出ないものは「ほかのタスクを探す」で名前から探して置ける。落としたときのやる日の書き換えは `src/web/grid.ts` の `placeOn`・`unplaceTo`、日ごとの予定の切り分けは `src/shared/flow.ts` の `timedOn`・`allDayOn`。

タブは **今日／ボード／一覧／受信箱（旧 未整理）／設定** の5つになる。ボードは上でビューを切り替える（最後に開いたビューを覚えておく）。全ビュー共通で「カテゴリで絞る」「シリーズ（親）も出す」（2026-10-20 に「子タスクを含める」から置き換え・既定オフ・並べるビューと日付のビューだけ・4-3）「依存待ちを含める」を付ける（依存待ち＝4-2 の、先にやるものが終わっていない未完了。2026-10-14 本人要望で追加・既定は含める・端末に覚える。ボトルネックは待っている側を数えるビューなので、そこでは出さずに常に含める）。データは `GET /api/tasks?view=all&doneSince=<7日前>`（未完了の全件＋直近の完了・中止）を1回取って、画面側で振り分ける。

### 7-9. PWA

- ホーム画面に追加すると全画面で開く。
- 画面の外枠（ページ・JS・CSS）はキャッシュして、起動を速くする。
- **アプリを更新（2026-10-20 本人要望「PWA だとリロードボタンが出てこないので、ホーム画面から外して追加し直している」）**: ホーム画面のアプリは開き直しても読み込み直さず前の画面のまま続くので、新しい版を出しても古い画面を使い続けてしまう。
  - **版**: ビルドごとにビルドした時刻を画面に埋め込み（`__VECTODO_BUILD__`）、同じ値を `version.json` に書く（`vite.config.ts`）。画面は開いたときとアプリに戻ってきたとき（`visibilitychange`）に `/version.json` を取り（端末のキャッシュを使わない・sw.js も素通し）、違えば上に「✨ 新しい版がある［あとで］［更新］」の帯を出す（「あとで」はその版のあいだ出さない）。設定の「アプリ」にも「この画面／最新」の版と［更新して読み込み直す］（`web/appVersion.ts`）。
  - **更新**: サービスワーカーを更新して（`registration.update()`・新しい sw.js は skipWaiting ですぐ入れ替わる）、外枠のキャッシュ（`task-app-shell-*`）を捨ててから読み込み直す。データのキャッシュ（`task-app-data-*`）と端末の設定・送信待ちは残す。`version.json` が取れない（つながっていない）ときは何もしない（外枠を捨てると開けなくなるため）。
  - **サーバの指示**: 名前にハッシュが付く `/assets` は `Cache-Control: public, max-age=31536000, immutable`、それ以外の画面のファイル（index.html・sw.js・manifest・version.json・アイコン）は `no-cache`（毎回確かめる）。
- **電波がなくても読むだけはできる**（2026-10-15 本人要望・旅行の持ち物リストを機内や PC が止まっているときにも見たい）。`sw.js` が読み取り（GET /api）をネットワーク優先で取り、取れた中身を端末（Cache Storage `task-app-data-v1`・新しい 300 件まで）に残す。つながらない・4 秒で返らないときは残しておいた最後の中身を返し、印 `x-vectodo-saved`（保存した時刻）を付ける。
  - 画面は印を見て（`web/offline.ts`）上に「📴 つながっていない（10/15 13:28 の内容）」の帯を出す。20 秒ごと・電波が戻った合図・「つなぎ直す」で取り直し、印の無い返事が来たら消す。
  - **書き溜めて後で送る**（要件 2-8 の第2段・2026-10-15 本人が選んだ）: クイックメモ・タスクの追加・ノートのチェックは、つながらなければ端末（localStorage `task-app.outbox`）に溜めて「つながっていないので溜めた」と出す。つながっていると分かっている間は送らずに溜める。帯に「送信待ち N 件」（押すと中身）。つながったら古い順に送って「溜めていた N 件を送った」（`web/outbox.ts`）。
    - ノートのチェックは「何番目の・どの文の項目を・付ける／外す」で溜め、送るときに今のノートを取り直して（`x-vectodo-live` を付けた読み取りは sw.js が素通し）その項目にだけ当てる＝溜めている間に Claude が項目を書き足していても消さない。場所がずれていたら同じ文の項目へ、見つからなければ送らずにお知らせ。送るまでは、溜めたチェックを表示に重ねて見せる（開き直しても残る）。
    - それ以外の書き込み（完了・やる日・ノートの文章など）は溜めず、「つながっていないので保存できなかった」と出す。ノートはつながっていない間はチェックだけできる（欄は書けない・並べ替え・下の道具を出さない・新しく書けない）。
    - 送れたか分からないまま切れた（届いていたのに返事が来なかった）ときは、同じものが2つできることがある（まれなので受け入れる）。
  - 残すのはおまけなので、端末に残せなかった（容量・ブラウザの都合）ときも読み取り自体は返す（2026-10-20・確認用の Chrome で保存に失敗して読み取りまで失敗していたのを直した）。
  - React Query は読み取りを電波が無くても投げ（`networkMode: 'offlineFirst'`）、書き込みは React Query に溜めさせない（`'always'`・溜めるのは outbox.ts）。
  - 残るのは一度開いた画面の中身だけ（開いていない週・タスクの詳細は読めない）。

### 7-11. 月と、Google の予定の重ね表示（v3・2026-10-14 本人決定）

### 7-12. シリーズの依存の図（v4・2026-10-14 本人決定）

- **置き場所はボードの「シリーズ」ビュー**（月の隣）。上の選択でシリーズ（＝子を持つタスク・要件 2-6）を選ぶ。終わったシリーズは選択の下のほうにまとめ、アーカイブしたカテゴリのものは出さない。**親の詳細の「子タスク」欄の「依存の図で見る →」、子の詳細の上の「シリーズの図で見る →」からも飛べる**（`/board?v=series&s=133`・詳細は閉じる）。子から来たときは `&f=140` を付け、図の中でその子を枠で光らせて真ん中まで送る（シリーズを選び直すと消える）。ボードの絞り込み・シリーズ（親）も出すは、このビューでは出さない。
- 中身＝その親の子（全状態・並び順どおり）。**親をまたぐ線の先は「外」のノード（点線の枠・親の名前つき）として描く**（要件 2-6）。孫は描かない（子のノードに「子 2/5」と出し、その子の詳細から図へ入る）。
- **「親なし」**（id 0）: いちばん上の段のタスクどうしに依存があるときだけ選択に出る仮のシリーズ。両端とも終わった線しか無いものは入れない。子との線は子のシリーズの図に出るので、ここでは数えない。
- **向き: スマホは上→下、広い画面（1024px 以上）は左→右**（本人決定）。並べ方は `src/web/board/dag.ts`（純粋関数）: 段＝最長の道（先にやるものが無ければ 0）、2段以上またぐ線は間の段に中継点を置いて途中のノードを避ける、段の中は重心法で交差を減らす（上下に8往復・交差が最少の並びを採る）、列は線の相手の平均に寄せて 1 以上あける。**線が1本も無い子は図の外の「まだ線がないもの」に並べる**。
- ノード: 番号・状態（✓・進行中・待ち・中止）・締切（過ぎたら赤）・カテゴリの色の点・タイトル2行（ノードの高さは2行が欠けずに収まる 70px）。**依存待ち・待ちは薄く**（4-2）、完了は緑、進行中は藍の枠。線は先→後の矢印で、先が完了なら緑、中止なら点線。
- **編集（2026-10-15 本人要望で作り直し）**: **ノードの出口の側（PC は右・スマホは下）の ● を押したまま、後にやるタスクの上で離すと 先→後 の依存ができる**（指でもマウスでも。引いている間は点線が指の先までのび、離すとつながるノードを藍の枠で示す。画面の端に寄せると図とページを送る。「まだ線がないもの」や点線の枠の外のノードへもつなげる）。同じ線がもうあれば「もうつながっている」。**線を押すと確認して外す**。循環はサーバが 409 で断り、トーストで知らせる。ノードを押すと詳細が開く。**「並び順どおりに一列につなぐ」**は、子に線が1本も無いときだけ出る（`chain-children`）。前の「つなぐ・外す」を押して2つ選ぶ形はやめた。
- **子タスクを足す（2026-10-15 本人要望）**: 親のシリーズを開いているときは、上の欄にタイトルを入れて Enter（か「追加」）で、その親の子を足せる（続けて何件でも・カテゴリは親から）。足したものは「まだ線がないもの」に出るので、● をドラッグしてつなぐ。「親なし」（id 0）では出さない。

### 7-13. ノート（2026-10-14 本人要望「今のメモとは別でもっとフリーなものを・Google Keep のようなシンプルな UI」）

- タブに「ノート」を足した（今日／ボード／一覧／受信箱／ノート／設定）。広い画面でも右の詳細の欄は出さない（幅いっぱいにカードを並べる）。
- 上に「メモを入力…」（☑ でチェックリストから書く）。カードはスマホ2列・タブレット3列・PC4列で、左上から右へ並べる（Keep と同じ読み順）。固定したものは「📌 固定」にまとめて先に。
- カードを押すと開く。**スマホは1枚の紙**（2026-10-15 本人要望「窮屈・フリーメモ感がない・入力に抵抗のない UI に」で作り直し）: 枠を付けずノートの色の紙が画面いっぱいに広がり、左上に「←」（戻る＝閉じる）、右上に 📌 固定・🗄 アーカイブ。文字の大きさは設定の「ノートの文字」で 小（本文 14px・タイトル 17px）／中（15・18・既定）／大（17・20）から選ぶ（端末ごと・`web/noteFont.ts`）。まわりに余白をとる。ダークの色は半透明なので、不透明な地の上に重ねる（重ねないと下の一覧が透けてタイトルが読めなかった・2026-10-15 本人指摘）。スマホでは地（とノートの色）を画面全体に敷き、キーボードが出たら書くところだけを隠れていない範囲に縮める（キーボードのまわりや後ろに下の一覧が透けていた・2026-10-15 本人指摘）。書くところは縦の flex なので、中身は縮ませない（キーボードが出るとチェックリストのタイトルが 8px につぶれて消えていた）。**何も無いところ（下の余白も）を押すと続きから書ける**（文章は末尾へ・チェックリストは最後の項目へ）。新しく書くときは本文にカーソルを置いて開く。下に ☑/¶（チェックリスト⇔文章）・🎨 色・🏷 ラベル・編集した時刻・🗑 削除をアイコンで並べ、キーボードが出てもその上に来る。**広い画面は真ん中の大きめのカード**（同じ並び・右下に「閉じる」・背景を押しても閉じる）。書いたそばから保存（0.6秒待って・新しいノートは中身が入ってから作る・開いて閉じただけなら保存しない）。閉じるときに空の項目を片付ける。Esc・背景を押しても閉じる。
- 長い文: タイトル・本文・チェックリストの項目は、どれも画面の端で折り返して中身の高さまで伸びる（項目が1行の入力欄で端から先が見切れていたのを直した）。スクロールは開いたノート全体の1つだけ。文章の上を指でなぞっても最後まで送れる。スマホでキーボードが出たら、開いたノートを隠れていない範囲（visualViewport）に縮めて、下の道具と書いている行がキーボードの裏に入らないようにする（2026-10-15 本人要望「見切れた文をスクロールして見に行けるように」）。
- チェックリストの並べ替え: 項目の左のつまみ（点 2×3）を押したまま上下へ（指でもマウスでも・つまみだけは触ってもスクロールしない）。指が隣の行の真ん中を越えたら入れ替え、上下の端に寄せている間はノートを送る。並べ替えるのは未チェックの項目だけ（2026-10-15 本人要望）。
- チェックリスト: Enter で書いている場所から項目を分ける（末尾なら空の項目を足す）、先頭で Backspace で上の項目につなげる、空のまま Backspace で消す、× で消す。複数行を貼り付けると行ごとに項目になる。チェックした項目は下の「チェック済み N 件」へ（畳める）。カードのチェックは見るだけで、どこを押しても開く（チェックは開いてから。2026-10-15 本人要望: 開こうとしてチェックを付けてしまうため）。
- 道具: 🎨 色（10色＋なし）・🏷 ラベル（付け外し・新しいラベルもここで）・☑/¶ チェックリスト⇔文章（行ごとに項目にする・項目を行に戻す）は下、📌 固定・🗄 アーカイブ（戻す）は右上、🗑 削除（確認あり）は右下。
- 上の検索（タイトル・本文・項目・ラベル）と、ラベルのチップで絞る。「🗄 アーカイブ」でアーカイブしたノートを見る。
